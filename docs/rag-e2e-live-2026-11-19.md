# 方案 A：真实 RAG 端到端验收

> 版本范围：本报告记录同日回答 Agent 升级前的固定检索流程。其后发现的“继续”丢失失败任务及流式回答截断问题、修复和专项真实验证见 [回答 Agent 修复报告](answer-agent-fix-2026-11-19.md)。本报告的并发延迟不代表升级后 Agent 的性能。

**本报告测试方案：A（默认），Qwen 稠密 + Milvus 内置 BM25。** 应用配置为 `RETRIEVAL_SPARSE_MODE=bm25`。下述 50 问、25 个答案、权限与版本检查、Edge 流程及 20 路并发结果均属于方案 A。方案 B（Qwen 稠密 + Qwen 稀疏）已完成此前的[检索专项 A/B 对比](rag-live-test-2026-11-18.md)，尚未单独完成同等应用端到端与并发验收。

完成日期：2026-11-19。应用已通过外部 PostgreSQL、腾讯 COS、Milvus、DeepSeek 和 Qwen 的完整流程验证。本次没有用 SQLite、内存索引或模拟模型替代运行中的服务。真实浏览器使用本机 Microsoft Edge，没有下载 Chrome 或 Chrome CLI。

## DeepSeek 截断修复

原失败响应的 `finish_reason=length`，4096 个输出 token 已用于推理，正文 JSON 尚未生成。这说明碰到了**请求的输出额度**，不能据此判断整个上下文窗口已满。上下文窗口容纳输入与输出，`max_tokens` 则限制本次生成；盲目设到模型最大值会增加时间与费用，也不能保证结构输出正确。[DeepSeek 请求参数](https://api-docs.deepseek.com/api/create-chat-completion/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

针对指代消解这种有原文证据约束的局部任务，默认采用非思考模式：

```dotenv
COREFERENCE_USE_DEEPSEEK=true
COREFERENCE_DEEPSEEK_THINKING=disabled
```

请求发送 `thinking: {"type": "disabled"}`，只作用于共用 DeepSeek 的指代消解调用。元数据、追问改写和答案生成不受该开关影响；独立模型适配器不发送 DeepSeek 专有参数。处理指纹包含有效思考设置，修改后重新上传可生成新版本，原版本在新版本就绪前保持可用。

结构化生成仍最多调用 3 次：初始 4096，仅当 `finish_reason=length` 时，下次提高至 8192，再至 16384。截断结果即使看起来是合法 JSON 也不接受；结构、偏移、原词和证据校验继续生效。

首次关闭思考的探针有 2 / 4 漏替换，原失败结果保留。随后服务端提供候选词及字符位置，并补充同段前文指代和歧义示例。最终真实探针 4 / 4 通过，覆盖跨段、同段、歧义保留及否定/数字/单位保留。

`get-api-key.md` 用新配置重新完整入库：8 次指代消解调用均请求 disabled、均以 stop 完成，共报告 302 个 completion token，无结构修复。非思考响应未返回 reasoning 明细，不能把缺失字段当成独立测量结果。Edge 上传的合成文档也保留了“它 → 银杉测试饮料”的修改记录与原文。

其余 7 份官方文档是在之前的思考配置下入库，仍是有效版本；本报告不把它们说成全部经过非思考模式重建。以上是小样本可靠性验证，不构成两种模式的通用质量比较。

## 检索与答案评分

本轮方案 A 使用 `qwen3.7-text-embedding` 稠密向量 + Milvus 原生中文 BM25，各召回 50，RRF k=60，远程 `qwen3.7-text-rerank` 选前 5。元数据和答案生成共用 `deepseek-flash`。入库时同时存储了 Qwen 稀疏向量供方案 B 使用，但本轮查询未使用该稀疏检索路径。

50 个问法对应 25 条预先标注事实。原始评测要求**指定文档中的标注原句出现在处理后正文中**，没有在看到结果后改标签。nDCG@5 按首个命中该标注事实的位置计算，同一事实在多个片段重复出现不重复计分：

| 评分口径 | Recall@5 | nDCG@5 |
|---|---:|---:|
| 原始严格正文匹配 | 94%（47/50） | 0.8803 |
| 补充诊断：原始证据映射 | 98%（49/50） | 0.9203 |

原始融合候选命中率为 96%（48/50）。两个正文未命中案例 `aliyun-04-1/2` 的“生成它的 API Key”经过指代消解变为“生成临时 API Key 的 API Key”；相关片段均已召回且保留完整原句。补充诊断只在原段落被分块**完整包含**时接受其原文证据，仍要求指定文档，避免把长段落中不属于当前块的内容误算为命中。补充指标与原始指标分别保留，不互相替代。

`aliyun-17-2` 仍未命中指定 `base-url.md` 原句，但前列的其他文档有明确的跨地域密钥限制。未事后扩大标注以提高原始分数。

25 个答案逐条对照主要标注事实及引用：25 / 25 支持该主要事实，引用均关联真实当前版本、可访问分块和原文。3 个资料不足问题均拒绝猜测。复核由本次开发助手完成，不是独立领域专家盲评，也不是逐项扩展断言的准确率：部分回答较冗长，案例 06、16、23 对不同资料的措辞差异作了不必要的“不一致”补充；拒答也可能介绍不相关的召回资料。生产质量仍需实际业务问题和专家复核。

前一轮两种稀疏方案的真实 A/B 仍见 [2026-11-18 报告](rag-live-test-2026-11-18.md)：重排序后两者均为 98% / 0.9203，没有证据支持更换默认 BM25。本次完成应用全链路，未重新进行双方案 A/B，不能直接把不同处理流程下的严格正文分数解释为模型退步。

## 流程、权限与故障恢复

API 验证了普通成员越权检索/下载被拒、跨用户会话不可读；撤销授权后历史答案和标题隐藏、引用不可读、后续问答被阻止。版本从 330 ml / 5 元更新到 500 ml / 6 元后，新答案只使用当前版本，旧引用失效。删除先逻辑下线，再由 Worker 清理外部文件和索引。退出登录后会话不可再使用。

在真实 Worker 正处理 `error-code.md` 时中断进程。中断前完成 397 / 561 张元数据卡片，租约过期后 attempts 从 1 变为 2，恢复检查时已到 402 张，最终完整发布 561 块。未发布半成品。网络暂时不可用期间的失败记录也保留，恢复后任务完成。

S3 删除和 Milvus 清理由独立检查确认实际完成，非仅检查任务标记。上传、删除、授权、问答、重试的审计事件均有 trace ID。

Edge 完成登录、上传、等待入库、查看分块卡片和修改记录、问答及追问、展开原文来源、更新、再次问答、删除及历史隐藏。浏览器文档从 250 ml / 8 元更新到 300 ml / 9 元，最后删除。检索调试页面显示真实稠密/BM25 排名、RRF 和重排序分数。

真实答案验收还发现原校验器禁止所有 URL，误拒文档已有的 endpoint。现在只允许逐字来自所引用片段的 HTTP(S) 地址；编造域名、增加路径/查询参数、替换占位符、引用未选中的来源都会被拒绝。补充了 Markdown 链接、中文标点及括号处理的回归测试，失败答案不进入有效历史。两次修复前的失败记录保留。

## 复现与产物

应用与 Worker 读取项目 `.env`，本次 API 为 `http://127.0.0.1:8001`，API 启动时使用 `RETRIEVAL_SPARSE_MODE=bm25`（方案 A）。验收状态与随机测试账号保存在本机被忽略的 `output/e2e-live`，账号文件不应公开或纳入版本管理。以下命令需已完成首次真实验收初始化：

```powershell
uv run python scripts/aliyun_e2e_live.py status
uv run python scripts/aliyun_e2e_live.py evaluate --resume
uv run python scripts/aliyun_e2e_live.py capacity
```

`--resume` 校验已发布版本、分块数及问题标签，匹配后才复用先前已完成的案例。它不会清除失败记录或把未执行案例计为成功；`lifecycle` 阶段会修改和删除专用合成文档，不应在已完成的状态上直接重复。

该脚本通过当前运行的 API 测试，不自动执行 A/B 切换。方案 B 应另建独立验收状态与产物，重新执行相关案例；当前 `--resume` 未校验检索方案，不应复用方案 A 的恢复结果作为方案 B 的评测。

主要证据：

- `output/e2e-live/evaluation.json`：8 份文档、50 次检索、25 个答案及 3 次拒答。
- `output/e2e-live/evidence-review.json`：原始与映射评分差异、主要事实及引用核验。
- `output/e2e-live/concurrency-20.json`：完整语料下 20 路问答及耗时。
- `output/e2e-live/lifecycle.json`、`storage-and-audit.json`：权限、版本、删除及跨存储核验。
- `output/e2e-live/coreference-non-thinking-summary.json`、`coreference-non-thinking.jsonl`：非思考调用记录。
- `output/e2e-live/jobs-before-worker-restart.json`、`jobs-after-worker-restart.json`、`ingestion-status.json`：恢复及最终状态。
- `output/playwright/live-non-thinking-coreference.png`、`live-browser-updated-answer.png`、`live-deleted-history.png`：Edge 结果。
