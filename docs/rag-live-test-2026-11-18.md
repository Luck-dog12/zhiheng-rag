## 真实检索结果

语料为此前下载的 8 篇阿里云官方 Markdown 快照，含 103 个代码块，解析清洗后生成 746 块。准备脚本验证原文件哈希及所有逐字标注证据均保留在分块中。独立远程 Milvus 集合写入及完整性检查耗时 **107.15 秒**，应用集合未被覆盖。

50 个问法来自 25 条人工标注事实，每条两个问法。方案 A 使用 Qwen 稠密向量 + Milvus 原生中文 BM25；方案 B 使用相同稠密向量 + Qwen 模型稀疏向量（IP）。每路召回 50，RRF k=60，最多 100 候选，Qwen 重排序取前 5。

| 指标 | A：稠密 + BM25 | B：稠密 + 模型稀疏 |
|---|---:|---:|
| 融合候选包含标注证据 | 100% | 100% |
| 融合 Recall@5 | 88% | 82% |
| 融合 nDCG@5 | 0.7721 | 0.6994 |
| 重排序 Recall@5 | 98%（49/50） | 98%（49/50） |
| 重排序 nDCG@5 | 0.9203 | 0.9203 |
| 重排序 MRR@5 | 0.9000 | 0.9000 |
| 检索链路 P50 | 0.945 秒 | 0.903 秒 |
| 检索链路 P95 | 2.629 秒 | 2.279 秒 |

链路时间包括共用的 dense&sparse 查询嵌入、两路检索与融合、远程重排序，不包括答案生成或文档入库；不是独立 dense-only 请求的性能，也不是 20 路并发基线。A/B 执行顺序逐题交替，仅进行一次顺序测试。

融合阶段逐题比较：A 胜 10 题，B 胜 5 题，35 题持平；重排序后的标注证据排名 50 题全部持平。本次语料未显示切换到模型稀疏向量能提高最终证据质量，保留现有 BM25 默认配置。延迟差异不能凭单次测试推广到生产环境。

## 未命中复核与评分边界

唯一严格未命中的问题为 `aliyun-17-2`：“北京的百炼密钥可以直接用于新加坡地域吗？”标注要求命中 `base-url.md` 中的特定原句。两种方案均将 `compatibility-of-openai-with-dashscope.md` 的“跨地域调用”片段排在第一，其中明确说明 API Key 绑定地域，跨地域调用会被鉴权拒绝；第二名的 `get-api-key.md` 也明确说明不能跨地域混用。

因此，该问题并非缺少支持答案的资料，而是严格单文档标注未覆盖等价证据。原始指标保持 98%，未在观察结果后修改标注来提高分数。人工复核片段及真实 chunk_id 保存在 `output/aliyun-live/manual-review.json`。该复核仅覆盖这个未命中案例，不等于对全部生成答案的正确性验收。

语料中错误码文档占 561/746 块，50 个问法也只有 25 条独立事实；结果适用于这组技术文档，不能等同于广泛业务质量。nDCG@5 按每个问题最先命中的标注事实计算，同一事实多次出现不重复计分。
