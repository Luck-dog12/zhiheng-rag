# 会话删除与检索片段数量验证

日期：2026-11-20。运行入口：`http://127.0.0.1:8004`。本次没有调整实际检索数量或切换 A/B 方案，仍为方案 A 的 `bm25` 索引配置。

## 数量含义

| 阶段 | 当前配置与行为 |
|---|---|
| 两路召回 | 混合检索默认稠密、BM25 各召回 50 条 |
| 重排序输入 | 融合、去重、权限和版本过滤后，最多 100 个候选参与评分 |
| 单轮交给 Agent 的片段 | 重排序前 5 个，少于 5 个则按实际数量返回 |
| Agent 累积证据 | 多次检索与历史证据复核可累积超过 5 个片段，逐轮评估相关性与覆盖情况 |
| 最终生成答案 | 从评估相关的证据中选择最多 5 个；无相关证据时说明资料不足 |

`ANSWER_TOP_K` 控制单轮选取和最终证据上限，默认 5，可配置 1–5；此次补齐显式选取跨轮证据时同样执行配置上限。最终片段不必等于某次独立检索的前 5 个，Agent 可以选择不同轮次的互补资料。

调试页原来将“候选总数”紧挨“重排序结果”显示，容易误解为全部用于回答。现在显示“本次选中 X 个片段，共 Y 个候选参与重排序”，其余候选折叠并标注“本次未选中”。页面数量使用后端返回的 `top_k` 和真实 `hits`，不再固定按 5 分割。接口同时返回 `sparse_mode` 与 `strategy`，防止响应类型过滤掉稀疏来源标记。

后续排序核验：最终顺序按 `qwen3.7-text-rerank` 的 `rerank_score` 降序决定，不是按稠密召回排名、BM25 排名或 RRF 分数，也不是随机。真实请求的前五名重排分数为 0.9995、0.8994、0.8668、0.8404、0.5690，第六名 0.4346；已校验全部 78 个候选分数降序，`hits` 恰好等于候选前五个。证据保存在 `output/retrieval-ranking-live.json`。同分按重排输入索引稳定排序。

为避免右侧得分被忽略，页面已将最终分数移到片段下方，明确显示“重排序第 N 名 · 得分”；前序标签改为“稠密/BM25 召回第 N 名”和“RRF 融合”。不同阶段分数量纲不同，不能互相比数值大小。跨轮问答中，Agent 仍可根据证据覆盖情况进一步选择片段，不将不同查询的分数直接混排。此次加强了 OpenAI 兼容与 DashScope 两种重排序适配器的乱序响应测试，相关 44 项回归通过，前端构建通过。

## 会话删除

- 桌面最近对话每行右侧新增删除图标；窄屏工具栏可删除当前选中会话。确认弹窗明确展示会话名称和删除范围。
- 删除当前会话会清空当前问答、输入框和引用面板，回到新对话；删除其他会话保留当前会话。取消不发送删除请求。
- `DELETE /api/v1/conversations/{conversation_id}` 在同一事务中删除问答记录和会话，保留知识库文档及删除审计。本人权限和 CSRF 均在服务端验证，管理员不能越权删除他人会话。
- 删除和问答启动共用会话行锁。仍有活动生成时返回 `409 conversation_busy`；超过 10 分钟的遗留 running 记录可清理，沿用既有问答恢复判定，超过当前最大问答时限。
- 无新增数据库迁移。
