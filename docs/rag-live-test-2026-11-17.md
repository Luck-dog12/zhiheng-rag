## 本轮修复

1. 将 `.env` 的 DeepSeek 展示名称 `deepseek-V4.1-flash` 修正为可调用的模型 ID `deepseek-flash`。已用当前账号的 `/models` 返回列表及真实生成验证。该 ID 与展示名称的区别见 [DeepSeek 官方模型接口](https://api-docs.deepseek.com/api/list-models/)。
2. 将 COS endpoint 修正为不含桶名前缀的地域地址；增加可配置的签名版本与寻址方式，COS 使用 `s3` / `virtual`。依据 [腾讯云 AWS SDK 兼容说明](https://cloud.tencent.com/document/practice/436/37421)。密钥保留原值。
3. 真实读写测试发现新版 boto3 的批量删除缺少 COS 要求的 Content-MD5，返回 HTTP 400。为序列化 XML 请求补充正确校验头，实际删除复测通过。依据 [COS DELETE Multiple Objects](https://cloud.tencent.cn/document/api/436/8289)。新增测试验证中文及 XML 转义后的请求体校验值，并在发起网络请求前拦截。

4. 指代消解默认改为 `COREFERENCE_USE_DEEPSEEK=true`，直接使用 `DEEPSEEK_BASE_URL/API_KEY/MODEL`，不要求独立模型凭证。仍执行结构化建议与原文证据校验；保留显式关闭共用配置后的独立模型接入能力。处理指纹包含实际使用的模型与选择开关，防止模型变更后误复用旧处理结果。

代码回归：`uv run pytest -q` 为 **90 通过、3 跳过**；跳过的是未显式启用的外部 PostgreSQL 专项测试。`uv run ruff check backend tests scripts` 通过。这些回归结果不代替真实业务验收。
